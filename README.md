# 現役ドラフトルーム 2026

ブラウザで球団の編成責任者となり、11球団のCPUと現役ドラフトの流れを体験する非公式Webアプリです。React / TypeScript / Viteで実装しています。

NPB公式の2026年度選手名簿・一軍成績と、出典付きの2026年推定年俸を使用します。対象条件・第1巡・第2巡の公表報道を反映していますが、年俸は2026年推定額を使用し、個別契約や議長の内部調整まで完全再現したものではありません。

## 開発

Node.js 24を推奨します。このクラウドタスクは既に隔離されているため、既存チェックアウトで作業し、明示的な依頼がなければGit worktreeを追加しません。

```sh
cd /workspace/bunshunyakyu-app
npm ci --no-audit --no-fund
npm run dev
```

開発サーバーはポート5173で起動し、同じサーバー上で利用状況の集計APIも動きます。選手データはローカルの静的データを読みます。集計にはNode.js内蔵のSQLiteを使うため、外部DBサービス・APIキーの取得は不要です。`.npmrc` は書き込み可能なチェックアウト内 `.cache/npm` にnpmキャッシュを置きます。

```sh
npm run build
npm test
python -m unittest discover -s scripts -p 'test_*.py'
CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e
```

システムにChromiumがない環境では、Playwrightの公式手順でブラウザをインストールしてから `npm run test:e2e` を実行します。ブラウザ試験はポート5174と一時DB・試験専用キーを使い、開発用のログと分離します。`npm run preview` は静的なビルド成果物の確認用で、集計APIは起動しません。

## アクセス・プレーの集計

`/admin` が管理画面です。管理キーでログインすると、日本時間の日別・時間帯別のアクセス数、推定利用者数、プレー開始人数、開始回数、完了回数、球団別回数、直近の開始・完了日時を確認できます。期間変更と日別CSV保存にも対応しています。

初回起動時に管理キーを暗号学的乱数で生成し、開発用は `.local-data/analytics-dev.key`、公開用は `.local-data/analytics.key` に権限600で保存します。このファイルをサーバー側で安全に確認し、管理画面に入力してください。キーをチャット、公開ファイル、クライアント用の `VITE_` 環境変数には含めないでください。既存キーを起動のたびに作り直すことはありません。

無料枠での本番公開は **Cloudflare Workers＋D1** を使います。ゲームと集計を同じHTTPS URLで提供します。公開手順と必要なアカウント設定は [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md) を参照してください。本番URL：[https://geneki-draft-room.takky416.workers.dev](https://geneki-draft-room.takky416.workers.dev)（2026-10-24公開）。プレーヤーのアカウント登録は不要です。

Node.js＋SQLite版をローカルで起動する場合は次の通りです。

```sh
npm run build
npm start
```

ポート3001でWebアプリと集計APIを配信します。このNode.js版を外部公開する場合は、HTTPSと書き込み可能な永続ディスクが必要です。Cloudflare版はD1を使うためNode.jsサーバーや永続ディスクの契約は不要です。

保存先・管理キーを環境変数で指定する場合は [.env.example](.env.example) と [docs/ANALYTICS.md](docs/ANALYTICS.md) を参照してください。管理キーはサーバー専用です。設定しなければ上記ファイルを自動生成します。ゲーム側で計測を停止してもプレーできます。

## 実装済みの機能

- 初回のスプラッシュと再開案内、コンパクトな12球団選択、リーグによる絞り込み。
- セの表示順は中日→阪神→広島→ヤクルト→横浜→読売。パは2026年公式順位（ソフトバンク→西武→日本ハム→オリックス→ロッテ→楽天）。エンジンの球団順とは独立。
- 選択球団に応じた背景・ボタン・サイドバー・発表演出のカラーと、現在の操作を示す進行ガイド。
- 自球団の候補選手提出、守備位置フィルターと選手詳細、他球団候補への希望投票。
- CPUの候補選考・投票・指名、自分の番までの進行、指名タイムライン。新しいプレーでは主力を保護した重み付き抽選で候補が変化。過去の保存結果は従来の選考で再現。
- 第1巡の指名連鎖と各球団1名の獲得・放出。
- 候補提出後のリスト取りまとめ、集計後の指名権発表、各球団の指名、第2巡結果の段階的な発表演出。スキップ・演出設定・動きを減らす設定に対応。
- 本文・操作16px、選手名18px以上、補足14px以上を基本にした文字サイズ。狭い画面では折り返して表示。
- 第2巡の獲得希望／放出のみ／不参加、希望順位付きの無条件・均衡条件の入札と成立判定。
- 結果一覧と「プレー結果を共有」。ブログ用の表付きコピー、文章の代替コピー、球団カラーのPNG画像に対応。結果のJSON保存ボタンは廃止。
- ブラウザ内の自動保存・再開。不正な保存データは合法な操作の再実行で検証。
- 2026年の利用者提供データをJSONで取り込む機能。
- スマホでは補助情報・指名履歴・参加状況を開閉式にし、選手の成績・年俸・対象外の理由・出典は詳細画面で確認。大きい文字のまま候補一覧をコンパクトに表示。
- 候補提出・投票・指名・結果表示・再スタート後に、次の操作見出しへ表示位置とフォーカスを移動。選択中や演出中には移動せず、一覧のスクロールも次の段階で先頭に戻す。
- キーボード操作、Escapeで閉じられるモーダルと、閉じた際の操作元へのフォーカス復帰。
- SQLite／Cloudflare D1へのアクセス・プレー記録、認証付き管理画面、日別CSV、計測停止設定。

未確定の候補選択は保存せず、候補提出・投票・指名など確定済みの進行を保存します。同時に複数タブで遊ぶ際の同期は実装していません。

## データ

`src/npb2026.json` は2026-10-24（日本時間）にNPB公式36ページから取得した1,067名の名簿と2026年度一軍成績のスナップショットです。ページURL、取得日、元HTMLのSHA-256を収録しています。名簿の支配下・育成の区分を反映し、育成登録選手は選択不可です。これは現役ドラフトの資格判定とは別です。

更新は次のコマンドで行います。通常の開発や起動時に取得し直す必要はありません。

```sh
python scripts/update_npb_data.py
# 同日キャッシュも更新する場合
python scripts/update_npb_data.py --refresh
```

公式サイトが次年度の名簿に切り替わった場合や構造が変わった場合は失敗させ、既存スナップショットを保持します。TLS検証と環境のHTTPSプロキシを維持します。取得並列数は3です。生HTMLはGit管理外の `.cache/npb/` に保存します。

詳細は [docs/DATA.md](docs/DATA.md)、指名モデルの範囲は [docs/RULES.md](docs/RULES.md) を参照してください。

## 今後の対人プレー

`src/engine.ts` はUI・ストレージ・通信から独立した純粋な状態遷移です。入力・乱数シードが同じなら同じ結果になります。CPU操作も人間と同じ指名検証を通ります。

現在はシングルプレーのみです。12人の同時参加には、サーバーを正とする進行管理、認証、ルーム、提出情報の秘匿、切断復帰、タイムアウト、操作競合の排除を別途実装する必要があります。ローカル保存をそのままオンラインの信頼境界には使いません。

年俸・条件データは `src/eligibility2026.json`。通常の起動時には更新せず、調査更新時に `python scripts/update_eligibility_data.py` を実行します。2026年推定年俸1,010名、公式FA資格者105名、前年現役ドラフト加入者12名を照合しています。年俸不明・外国人区分未照合は選択対象外にします。海外出身でもNPBドラフト記録で日本人扱いを照合できた7選手は出生地による保留を解除し、育成や戦力外など他の除外条件は維持します。戦力外・退団・引退報道に一致する106選手を除外しています。同日内の報道更新を取得する場合は `python scripts/update_eligibility_data.py --refresh` を使います。画面上の「仮対象・仮判定・未確認」や補強ポイントの表示は廃止しました。個別契約など確認範囲の限界は [docs/DATA.md](docs/DATA.md) に記録しています。旧版の保存はv1に保持し、新ルールではv2を使います。

提出済みの進行中・完了済みの公式データのゲームは、保存時の選手条件と成績を使って再現します。更新した対象選手は「新しいドラフト」から反映します。候補提出前の保存は最新データへ更新します。
