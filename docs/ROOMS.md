# ルームと対人プレー

入口は「ルームを作る」「ルームに入る」の2つ。ニックネームと6桁の番号で参加し、球団を選ぶ。同一球団は先着1人。主催者以外の準備完了を確認して開始する。1人でも開始でき、空席は従来と同じ現実性・ランダム性のあるCPUが担当する。開始後の新規参加は受け付けず、既存参加者の再接続だけを認める。

## 構成

- Reactの既存の候補選択・指名演出・サウンド・共有画面を使う。
- Cloudflare Workerがルーム作成と番号による参加を受け付ける。
- ルームごとにSQLiteストレージのDurable Objectを1つ作る。番号は暗号学的乱数で生成し、初期化を直列化して衝突時に再抽選する。先頭のゼロも保持する。
- WebSocket Hibernation APIで接続を維持し、参加者ごとに内容を秘匿したスナップショットを配信する。待機のために常駐タイマーを回さず、Alarms APIで次の期限に起動する。
- 既存のD1はアクセス集計専用。名前・会話・候補・入札を集計DBへ入れない。
- ローカルのVite開発サーバーとNode公開サーバーは、同じRoomCoreを`ws`＋Node SQLiteのアダプターで動かす。ローカルでも別のブラウザから同じ番号で参加できる。

`src/engine.ts`の合法な候補提出・投票・指名・入札判定を共通利用する。人間の複数球団分の提出内容を渡せるようにし、省略した球団は既存のCPU判断を使う。従来のローカル保存は従来の再現方法で引き続き再開できる。新しいルームは全員が同じ2026年公式名簿・条件データを使い、ブラウザだけの取り込みデータは送信・適用しない。

## 正しい進行と非公開情報

サーバーだけが本物の乱数シードと確定した進行を持つ。各操作は参加者・段階・指名番・選手の資格・既提出かを検証し、ストレージへ保存してから配信する。リクエストIDを最大128件保持し、再送の二重適用を防ぐ。競合した操作は直列処理する。保存に失敗した場合は処理前の状態へ戻す。

- 候補：全員が提出するまでは自球団分だけを返す。全員確定後に12球団分を公開する。
- 投票：全員確定までは自分の投票だけを返す。確定後に指名順と得票を公開する。
- 第2巡の参加意向：全員確定してから公開する。
- 第2巡の希望順位・条件：全員確定までは自分の入札だけを返す。確定後に既存ルールで一括判定し、成立した指名を1件ずつ発表する。

画面で隠すだけでなく、HTTPレスポンス・WebSocketの配信データそのものから他人の未確定情報を除く。参加者の認証キーのハッシュも配信しない。チャットや進行係の通知へ提出内容を自動掲載しない。

## 時間・切断・発表

候補・投票・参加意向・入札・人間の指名は、それぞれ3分。確定すると待機画面で提出済み球団数を表示する。時間切れの場合はCPUがその操作を代理で行い、切断中の参加者ならCPU担当に切り替える。同じ参加キーで再接続すると操作に復帰するが、確定済みの選択は巻き戻さない。

主催者は一時停止できる。再開時は停止していた時間だけ期限を延ばす。主催者の切断が1分続いた場合は、接続中の参加者へ主催権を引き継ぐ。開始前は主催者が未接続の参加者を外すこともできる。明示的に退出した参加キーは、残っているWebSocketを含めて無効化する。

候補の取りまとめは7秒、指名順発表は14秒、選手の発表は1件22秒を上限として共有する。端末ごとの音声・自動送り設定や非表示状態は、他の参加者のサーバー進行を止めない。主催者の一時停止は全員に適用する。1人だけが操作するルームでは、発表完了またはスキップの通知に合わせて先へ進めるので、消音時にも毎回22秒待つ必要はない。他の参加者がいる場合、この早送り操作は拒否する。

第2巡は全入札から最終結果を一度だけ確定し、その後は表示する指名の番号だけを進める。接続断やスキップによって未成立の途中結果を作らない。

## 名前・チャット・保存期間

名前は16文字、チャットは240文字まで。リアクションは定型文を使う。名前の重複、制御文字、連投（10秒間に5件超）を拒否する。本文はReactの文字列として表示し、HTMLとして実行しない。チャット履歴は最大80件で、UTF-8の大きな本文と多数の入札が重なった場合は古い会話から減らし、保存値を110,000バイト以内に保つ。

PCでは開閉できる横のパネル、スマホや指名発表中ではモーダルの引き出しで表示する。閉じている間は未読件数を表示する。球団・参加者名・進行係の発言を区別し、時刻は日本時間で表示する。

待合室は作成から2時間、進行中は開始から最大24時間、結果は確定から2時間で期限切れとなる。期限のアラームで会話・名前・参加キーを含むルーム状態を削除する。終了結果を長期間残したい場合は既存のテキストコピー・PNG保存を使う。

## 接続情報とAPI

参加時に256ビット相当のランダムな参加キーを発行し、ブラウザのローカルストレージへ保存する。サーバーにはSHA-256ハッシュだけを保存する。URLに参加キーを含めず、HTTPはAuthorizationヘッダー、WebSocketはサブプロトコルで渡す。プレーヤーのCloudflare認証・アカウント登録は不要。別端末への本人移行・パスワード・公開マッチング・観戦専用参加は今回の範囲に含めない。

- `POST /api/rooms`：作成。
- `POST /api/rooms/:code/join`：開始前の参加。
- `GET /api/rooms/:code`：認証済みの自分用状態。
- `GET /api/rooms/:code/socket`：認証済みWebSocket。
- `POST /api/rooms/:code/actions`：HTTPからの操作。通常の画面はWebSocketを使う。

別オリジンからの操作、過大な本文、ルームの大量作成・参加を拒否する。ルーム番号の一覧APIは用意しない。

## ローカルと試験

`npm run dev`で集計APIとルームAPIを同時起動する。ローカルの保存先は`.local-data/rooms-dev.sqlite`、`npm start`では`.local-data/rooms.sqlite`。`ROOMS_DB_PATH`で変更できる。Node版は`tsx`で共通TypeScriptを読み込む。Cloudflare版に`ws`やNode SQLiteは含めない。

単体試験は時計と保存先を差し替え、1人＋11CPU・12人・同時提出・非公開情報・重複と不正操作・再起動・切断復帰・一時停止・期限切れまで確認する。ブラウザ試験は別々のブラウザコンテキストで参加・会話・再接続・通しのプレー・共有・集計を確認する。Playwright専用のViteサーバーだけは`ROOMS_TEST_FAST_PRESENTATIONS=true`により発表時間を短縮する。人間の操作期限・認証・判定は変えず、Cloudflareにはこの試験設定を実装・配信しない。
