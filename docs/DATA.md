# 選手データと確認範囲

## 公式スナップショット

- 取得日：2026-10-24（日本時間）。取得日以降の移籍・契約変更は自動反映しません。
- NPB公式の2026年度選手一覧12ページ、2026年度個人打撃成績12ページ、個人投手成績12ページから1,067名を収録。
- 名簿URLは `https://npb.jp/bis/teams/rst_{team}.html`。年度がパスに入らないため見出しが2026年度であることを検証します。
- 成績URLは `https://npb.jp/bis/2026/stats/idb1_{team}.html` / `idp1_{team}.html`。
- 保存項目：公式ID、氏名、所属、守備位置、背番号、生年月日、投打、登録区分、注記、一軍成績、出典。
- 投球回の `11.2` は11回2/3を表す文字列です。一軍成績行がない選手は `stats: null` とし、欠測を架空の成績で補いません。OPSは公式出塁率＋長打率の表示用の和です。
- 選手名の空白・投打記号を正規化して球団別に対応付け、公式IDは名簿リンクから取得します。全ページの年度・構造・重複IDの検証が通った場合だけ出力を置換します。

元HTMLのSHA-256は取得内容の識別用で、第三者の署名や候補資格の証明ではありません。写真・公式ロゴは使用せず、球団マークは独自の文字図案です。

## 資格情報と年俸

`src/eligibility2026.json` を名簿の公式IDで結合します。名簿の `eligible` は支配下登録の内部フラグで、最終資格は `eligibilityOf` が年俸・除外情報を合わせて判定します。

ユーザーとの合意により、2026年推定年俸を実開催で用いる翌季年俸の代理とします。gurazeni.comの2026年球団別一覧を出典とし、氏名または背番号・守備位置と生年月日が一意に対応する1,010名の金額を収録しています。未照合57名を0円などで補完しません。

公式FA資格者105名と前年現役ドラフト加入者12名はNPBのIDで照合し除外します。育成、年俸1億円以上、戦力外・退団・引退報道も除外します。5,000万円以上1億円未満の選手を含める提出には通常枠2名以上が必要です。

非公表の複数年契約、過去FA行使の全履歴、開催時の契約保留名簿やシーズン終了後の加入・支配下移行を全選手について確定できたデータではありません。実際の非公開の提出候補を表すものでもありません。こうした内部の確認事項は保持しますが、ゲーム画面に「仮対象・仮判定・未確認」を繰り返し表示しません。成績、年俸、対象外の理由は「詳細」にまとめ、一覧は氏名・守備位置・年俸を中心に表示します。守備位置の絞り込みを残し、氏名検索と補強ポイントの表示は廃止しました。

## 更新と保存済みゲーム

```sh
python scripts/update_npb_data.py
python scripts/update_eligibility_data.py
# 同日中に追記された報道や訂正を取り直す
python scripts/update_eligibility_data.py --refresh
# 年俸等を取り直さず、戦力外・退団・引退等の追記だけを反映
python scripts/update_eligibility_data.py --departures-only --refresh
```

通常起動時には再取得しません。生HTMLはGit管理外の `.cache/npb/` と `.cache/eligibility/` に日別保存し、出典URL・取得日・ハッシュをスナップショットに記録します。`--refresh` で当日キャッシュも更新します。取得に失敗した際、既存スナップショットを空のデータで上書きしません。

個別記事の対応表は通常の全更新・`--departures-only` の両方で検証し、再生成で個別報道の除外を失わないようにします。`--departures-only` は確認できた除外理由だけを追加します。一時的な記事の欠落で以前の除外を解除せず、年俸・FA資格等の既存情報とその取得記録を保持します。

候補提出前の公式データのゲームは最新の条件を使います。提出済み・結果表示済みのゲームは、保存した選手条件と成績をID・型・範囲で検証して復元し、候補や指名結果を変えません。「新しいドラフト」で最新の条件に切り替わります。

進行中のルームでも受理済みの候補を維持します。後から加わった退団報道によって候補の集計・投票・指名を停止させず、提出済み候補にはその旨を表示します。未提出の新規候補には最新の除外情報を適用します。更新前の画面から対象外の候補が送られた場合も、HTTP 400と候補の選び直しを案内するメッセージを返し、接続障害として扱わないようにします。候補は受理せず、同じ段階で正しい候補を再提出できます。

## CPUと利用者データ

CPUの候補選考・参加判断・適合度は独自のゲーム設定で、実球団の意向ではありません。候補の重み付き抽選と主力保護は [RULES.md](RULES.md) に記録しています。需要設定は内部の選考にのみ使用し、補強ポイントとして画面に表示しません。

利用者JSONは `version: 1`、`season: 2026`、2026年内の有効な `asOf`、各球団2名以上の選択可能な選手が必要です。ID・正規化氏名の重複、不正な守備位置・球団・URL・日付を拒否し、1MB・1,500名までとします。これは形式検査で、出典や資格の照合ではありません。追加の未検証成績を公式成績として取り込みません。

`src/data.ts` の72名は旧操作確認用の過去所属参考データです。現在の既定データではなく、過去の保存を再開するため残しています。

## 男性アナウンスの静的音声

`src/maleVoice2026.json` は読み上げ文と `public/audio/voice-male-v4/` のMP3を対応付ける。日本語男性モデル `ja-JP-KeitaNeural` を用い、低音化・速度変更をせず、名前と本文を同じ通常速度で生成する。名前の読みは「苗字、名前」のように最初の空白を読点へ変える。音声前後の無音を除去済み。587本で、プレー中は必要な発表の音声だけを取得する。同一サイトから配信し、プレーヤーの情報や選択を外部TTSへ送らない。

更新は `scripts/build_male_voice.py`。任意の生成作業でのみ `edge-tts==7.3.1` とFFmpegが必要（ゲームの起動・ビルド・デプロイには不要）。例えば `python -m pip install --target /tmp/genneki-tts edge-tts==7.3.1` の後、`PYTHONPATH=/tmp/genneki-tts python scripts/build_male_voice.py`。既存の検証済みCAストアとプロキシを使い、TLS検証を無効化しない。生成済みファイルは再利用し、対象の読み上げ文が増えたときだけ追加生成する。元の `public/audio/voice-male-v2/` と `scripts/voice-source-v2.json` にある通常速度の本文はそのまま再利用し、低速だった名前と文言を変更した案内は通常速度で作り直す。FFmpegでは前後の無音調整だけを行い、ピッチ・速度・フォルマント・残響などを声へ加えない。v2・v3音声は更新前から開いているページの互換性のため配信も維持する。音声の生成・加工が完了してからアプリをビルドする。
