# 2026年推定年俸を用いるシミュレーションルール

ルールID：`2026-salary-proxy-v2`。ユーザーの合意に基づき、2026年推定年俸を翌季年俸の代理として使用する。2027年俸を用いる実開催時の厳密な資格判定とは異なる。出典と過年度からの変更は [RULE_RESEARCH.md](RULE_RESEARCH.md) に記載。

## 候補資格

- 2026年度公式名簿・成績はNPB。推定年俸はgurazeni.comの2026年度一覧で氏名または背番号・守備位置と生年月日を照合。1,067名中1,010名の金額を収録。
- 公式FA資格者105名、2025年現役ドラフト加入者12名をNPBの選手IDで照合し除外。育成登録、2026年俸1億円以上も除外。
- 日刊スポーツの退団一覧と個別記事を球団・公式IDで照合し、10月27日確認分までの戦力外・退団・引退報道に一致する156名を除外する。球歴中の過去の退団やコーチ退任は選手の現在の退団と混同しない。これは開催時の契約保留名簿の確認に代わるものではない。
- 金額未収録は選択対象外。外国出身者は国籍・外国人扱いを名前や出生地だけで決めない。NPBの日本人選手ドラフト記録とIDで対応付けた7選手は国内扱いとし、区分を照合できない選手は引き続き選択対象外とする。育成・戦力外等の別条件は維持する。
- 複数年契約、過去のFA行使、開催時の契約保留名簿等は全選手を確認できていない。画面では「仮対象」「仮判定」「未確認」という反復表示をせず、データ説明に使用年俸と情報源を示す。CPUにも同じ候補除外を適用する。
- 2026年10月14日の改定を日刊スポーツと翌15日のスポニチ本文で再確認。7月31日までの通常トレード等による加入は、それだけを理由には除外しない。前年現役ドラフト加入者の除外とは独立する。開催年の年度連盟選手権試合終了翌日以降の譲渡獲得・育成から支配下への移行は除外対象。選手別の加入・昇格時期は最終照合が必要で、候補画面とルール説明にもこの違いを明記する。
- 原則2名以上。5,000万円以上1億円未満を1名含める場合は、5,000万円未満を確認できる選手2名以上と合わせ、計3名以上。例外を2名、1億円ちょうど、金額不明を通常枠と数える提出を禁止する。
- 利用者取り込みデータの `eligible` は利用者の確認フラグとして扱う。未収録の年俸を推測で0円にせず、年俸不明は例外枠の通常2名には数えない。

## 第1巡

各球団が他球団の候補を1名予備指名し、所属球団の得票数で暫定順位を決める。同票は2026年新人ドラフト第2巡順：楽天、中日、ロッテ、ヤクルト、オリックス、広島、日本ハム、DeNA、西武、巨人、ソフトバンク、阪神。根拠はNPB公式2026年選択選手一覧の球団順とサンスポの解説。

最初は暫定順位1位が予備指名した選手を獲得し、その元所属球団に指名権が移る。既に獲得済みの球団へ戻る場合は未獲得球団の暫定順位で再開する。予備指名先が指名可能な限り別選手へ変更できない。既に放出済み等で指名不能なら、指名可能な別候補を選ぶ。11番目の指名は12番目の球団から選ぶ。全球団が各1名獲得・1名放出して終了。

## 第2巡

1. 獲得希望で参加／放出のみで参加／不参加を選択する。
2. 12球団の意向を表示し、自球団の意向・入札条件・希望順位を再確認する。確定前は意向変更可能。CPUの意向はシードで決まり、この画面では固定。これは実球団の意向の再現ではない。
3. 参加確定後は不参加へ切り替えられない。獲得希望の球団は1名以上の希望を優先順付きで入札。
4. 入札は「無条件」（人数増減を許容）または「獲得と放出が均衡する場合のみ」の2条件。
5. 無条件を優先し、同条件は第1巡の実際の指名順の逆順を優先する。参加球団の残り候補から、獲得・放出が各最大1名になる成立可能な組合せを探索する。
6. 均衡条件は獲得と放出が両方成立、または両方不成立の場合だけ受理。3球団以上の交換も扱う。放出のみ、獲得のみ、不成立も結果として認める。

報道は入札条件と競合順位を示す一方、NPB議長による複数の成立可能な組合せの内部調整手順までは公開していない。この実装は優先順位上位の入札・希望順から、全条件を満たす組合せを採用する決定的な調整方式。単純な貪欲法で後続の均衡条件を壊さず、成立可能性を全体で検証する。実際の議長の判断結果との完全一致を保証するものではない。

## 保存と再現

旧版はルールが異なるため、保存キーをv2に分ける。旧v1記録は消去せず保持し、初回に案内する。v2では候補提出・予備指名・指名・第2巡意向・確定入札を合法な遷移で再実行して保存データを検証する。第2巡の未確定な希望選択は保存対象外。

## 発表演出

候補提出後の12球団のリスト取りまとめ、指名順、各球団の指名、第2巡の成立結果は、発表待ちから結果表示へ段階的に進む。発表画面は演出部分の高さを抑え、待機中・発表後とも操作ボタンをスクロール領域の外に置く。CPUを自分の番まで進める場合も各指名を順に表示する。演出は結果・指名順・乱数を変更せず、発表した時点の合法な状態だけを保存する。待機中に再読み込みした場合は直前に保存した状態へ戻る。スキップ時は残りの合法な指名まで進み、二重指名しない。演出の有無は端末に保存し、ブラウザの「動きを減らす」設定では演出を省略する。

自動送りは初期設定でオン。指名順と各球団の指名を1.8秒待って発表し、結果を3.5秒表示して次へ進む。CPU区間は自動的に開始し、自分の指名番で必ず停止する。候補提出後の投票、指名する選手の選択、第2巡の参加・入札の確定を自動操作しない。演出なし・動きを減らす設定ではCPU区間を即座に進めるが、自分の選択は同様に停止する。

自動送りは画面上部と発表中のボタンで変更でき、端末に保存する。非表示のタブでは待機・自動送りタイマーを止め、戻った後に表示時間を取り直す。手動の次へ、スキップ、自動タイマーが重なっても同じ発表を二度進めない。再読込は最後に発表済みの状態から再開する。

発表画面の配色は指名した球団（獲得球団）へ切り替える。メインカラーとサブカラーは12球団分を `presentation.ts` に定義し、選手名はメイン色の帯とサブ色の縁で表示する。ゲーム本体の操作球団は変えず、発表画面だけがその球団の配色を持つ。PNGの結果画像にも両色を使う。

## CPU候補の選考（realistic-v2）

公式の対象条件と、CPUが放出候補を選ぶ編成判断は区別する。ルーキー・ドラフト上位という理由だけで公式の対象外にはならない。自球団のGMは制度上の対象選手を選べる。

新しいゲームのCPUは、適格・通常年俸枠から以下を保護する。公開情報からの保守的なゲーム設定であり、実球団の非公開リストの再現ではない。

- 2026年末の年齢が24歳以下。
- 2025年ドラフトの全指名選手（2026年のルーキー。育成指名後の支配下移行を含む）。
- 2023～2025年の支配下ドラフト1～3位（入団3年以内の上位指名）。過去の上位指名を永久に対象外にはしない。
- 野手：60試合以上、100打席以上、5本塁打以上、40打席以上でOPS .750以上のいずれか。捕手は25試合以上でも保護し、控え捕手の重要性も考慮する。
- 投手：20登板以上、30投球回以上、3勝以上、3セーブ以上、または10投球回以上で防御率3.00以下。投球回の小数表記をアウト数に変換して境界を扱う。

残りの選手から、出場機会・年齢・年俸・内部の守備位置需要に重みを置き、2名を重複なく抽選する。一軍での出番が限られた選手を中心にする。候補不足でも保護選手で穴埋めしない。現在の公式データでは球団ごとに4～11名の抽選プールがあり、100シードで全12球団が少なくとも6通りの候補ペアを生成することを検証している。

公式ドラフト36ページと個人プロフィールの対応は `src/cpuDraft2026.json`。更新方法と氏名変更の照合は [DATA.md](DATA.md) に記録する。起動時にインターネットから取得しない。

`cpuNominationModel: realistic-v2` を保存する。提出済みの `varied-v1` と、それより古い印のないv2ゲームの選考をそれぞれ保持し、再読込時に候補・結果を変えない。v1の抽選関数と基準は互換性のためそのまま残す。新しい候補基準は「新しいドラフト」から適用する。

## ブログ等への共有

共有するのは操作球団、獲得・放出、12球団の指名結果、データ名、非公式・2026年推定年俸使用の注記、アプリURL。保存用シード、内部選手ID、ブラウザID、プレー計測IDは含めない。コピー操作は獲得・放出と12球団の結果をプレーンテキストでクリップボードへ書き込み、ブログ等への貼り付けは下の説明で案内する。共有画面ではコピーされる全文を常に読み取り専用の欄で表示し、その同じ文字列をコピーする。コピー不可の場合はこの欄へフォーカスして全文を選択する。PNGは端末内で生成し、外部へ自動投稿しない。

パ・リーグの選択順は [NPB 2026年度チーム勝敗表](https://npb.jp/bis/2026/stats/std_p.html) を2026-10-24に確認。通常の起動時に再取得しない。

公式データ更新時、提出前は最新の資格情報を使用する。提出後・結果表示済みのゲームは保存時の条件・成績を検証して読み戻し、候補や指名を変えない。新しいドラフトでは最新データを使用する。

## サウンドと指名読み上げ

初期状態は消音。ゲーム上部と発表画面の「音：オン／オフ」で全体を切り替え、隣の設定からBGM・効果音・読み上げ、共通音量を変更する。設定は `geneki-draft:sound:v1` に保存し、ゲームのシードや保存状態を変えない。保存済みのオン設定は、ブラウザの制限に合わせて最初の操作から再開する。

BGMは短調のピアノ和音と弦の持続音・残響をWeb Audioで合成し、高音の短いアルペジオは使わない。待機は大太鼓風の低い打撃を0秒・0.58秒・1.16秒の3回鳴らす。25msの柔らかい立ち上がり、45～155Hzへ落ちる共鳴、480Hzの低域フィルターと残響を使い、細かいノイズの連打はしない。発表も大太鼓を主役とし、控えめなシンバル・和音を重ねる。効果音の出力を従来より強め、設定画面に試聴ボタンを置く。読み上げ中はBGMを下げ、全体のコンプレッサーで過大なピークを抑える。既存楽曲・会議中継の音源は使用しない。

読み上げの基本はアプリ自身が配信する日本語の男性音声（KeitaNeural）。対象選手・共通案内を587本のMP3として事前生成し、OSの標準音声が女性でも同じ男性音声で再生する。「第〇巡獲得希望選手・獲得球団の略称」、選手名、「ポジション・元の所属球団の正式名」の3区切りにする。低音化・タイムストレッチを外した自然な男性音声を使い、本文も名前も通常速度に統一する。読みの苗字・名前の間の最初の空白を読点に置き換え、音声モデルによる自然な区切りを付ける。登録名が一語の選手は分割しない。「巡」は「じゅん」、守備位置は「がいやしゅ・ないやしゅ・ほしゅ・とうしゅ」を明示する。前後の余分な無音を除き、通常120ms・名前の前1100ms・名前の後800msの間隔とし、各発表の3音声を並行して先読みする。

未収録の取り込み・旧データの文章には、利用可能なら男性と分かる端末音声で対応する。女性音声には自動的に切り替えない。録音ファイルや端末音声が使えない場合は該当箇所を飛ばしてゲームを継続し、読み込みエラーを設定画面で案内する。プレー中の有料API利用や外部の音声配信はない。特定の実在人物の声を模倣しない。

第2巡の入札はゲームルールどおり一括で成立判定し、合法な結果を変えずに1件ずつ発表する。各カードは指名球団の配色・選手名・ポジション・移籍元・現在の件数を表示し、読み上げ後の自動送り／手動送り／一括スキップに対応する。部分的な第2巡結果を保存データに作らず、最初の発表で成立済みの結果全体を保存する。途中で再読み込みした場合は確定済みの最終結果へ戻る。

発表画面の自動送りは読み上げ完了後から3.5秒待って進める。設定画面を開くと発表を一時停止し、閉じると現在の発表を最初から読み直す。手動送り・スキップ・消音・非表示で読み上げを取り消し、古い完了通知が次の発表へ干渉しないようにする。音声エンジンのエラー・完了通知漏れにはタイムアウトを設け、進行を止め続けない。演出を省略した場合は結果の確定後に読み上げ、画面操作を待たせない。
