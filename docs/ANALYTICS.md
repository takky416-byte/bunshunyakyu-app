# 利用状況の集計

## 数字の定義

| 指標             | 定義                                                                                                     |
| ---------------- | -------------------------------------------------------------------------------------------------------- |
| アクセス数（PV） | ゲーム画面を読み込んだ回数。再読み込みも含む。管理画面とAPI呼び出しは含まない。                          |
| 推定利用者数     | 期間内にアクセスまたはプレーしたブラウザ識別IDの数。                                                     |
| プレー開始人数   | 期間内に新しいプレーを開始したブラウザ識別IDの数。                                                       |
| 開始回数         | 球団選択後「この球団ではじめる」を押した回数。保存ゲームの再開は含まない。                               |
| 完了回数         | 結果画面に到達した回数。再読み込みでは増えない。開始が集計期間外でも、期間内に完了を受信した場合は含む。 |
| 未完了           | 開始記録があり、完了イベントを受信していないもの。現在プレー中の人数を意味しない。                       |

すべてサーバー受信時刻を日本時間で集計します。日別人数の合計と期間全体の人数は、同じ識別IDの再訪があるため一致しない場合があります。時間帯別グラフは指定期間の最終日について、0〜23時それぞれに新しくプレーを開始した推定人数を表示します。

ユーザー登録や端末のフィンガープリントは使いません。同じ人でも別端末・別ブラウザ・ブラウザデータ削除後は別に数えます。ボットの偽装、計測拒否、通信失敗による欠測を完全には防げません。請求・監査用の厳密な人数ではありません。

## 保存内容・プライバシー

- 保存するのはランダムなイベントID・ブラウザ識別ID・プレーID、種類、球団ID、サーバー受信時刻、開始／完了時刻。
- 氏名・メールアドレス・IPアドレス・User-Agent・ページのクエリ文字列・選択した選手・ゲーム内容はDBに保存しません。
- 接続元アドレスはリクエスト制限のため短時間メモリ上で使用しますが、DBやアプリのアクセスログには書き込みません。ホスティング側のリバースプロキシ等のログは別途管理が必要です。
- ブラウザ識別IDと計測設定はlocalStorage、未送信イベントはタブ別のsessionStorageに保存。未送信イベントは最大100件、送信バッチは20件まで。
- フッター「利用状況の計測」から停止可能。識別IDと未送信イベントを削除し、新しいイベントの送信を停止します。既に受信したサーバー側の記録は削除しません。
- `navigator.doNotTrack === '1'` またはGPCが有効な場合は計測しません。計測が無効でもゲームは動きます。
- 記録は直近180日を集計対象にします。Node.js版は毎時および記録・集計時、Cloudflare版は日本時間0:10のCronで古い記録を削除します。プロセス停止やCron失敗時は次回実行まで物理削除が遅れる場合があります。
- 古いログの削除はSQLiteからの論理削除です。バックアップやストレージ上の未使用領域まで消去する仕組みではありません。

## 重複と送信失敗

イベントIDで再送を排除し、さらにプレーID＋イベント種別の一意制約で、結果画面の再読み込みや別タブからの完了送信を重複計上しません。開始と完了は同じブラウザID・球団に紐付け、異なるIDからの完了は拒否します。開始記録のない完了は数えません。

通信障害時はゲームを止めず、タブ内に保持したイベントを最大60秒間隔で再送します。終了時にはBeacon送信も試します。再送した記録の日時は受信時刻になるため、オフラインで実際に遊んだ時刻を正確に復元するものではありません。タブを閉じた場合など、未送信ログが失われることもあります。

計測追加前の保存ゲーム、計測停止中に開始したゲーム、停止・再開で識別IDが変わったゲームの開始／完了は遡って加算しません。

## 管理画面と認証

管理画面：同じサイトの `/admin`。集計APIは管理キーによるBearer認証が必要です。キーは入力後の画面メモリにだけ保持し、URL・localStorage・sessionStorageには保存しません。再読み込み時には再入力してください。ログアウトすると画面のキーと集計を破棄します。

Cloudflare版はWorker Secret `ANALYTICS_ADMIN_KEY` を必須とし、未登録なら管理APIを503で閉じます。`npm run cloudflare:admin-key` で生成・登録し、所有者用の控えを `.local-data/cloudflare-admin.key` に非公開で保持します。

Node.js版の管理キーはサーバーの `ANALYTICS_ADMIN_KEY` を優先します。未設定なら、`ANALYTICS_ADMIN_KEY_FILE` または既定の非公開ファイルから読み、ファイルがなければ32バイトの暗号学的乱数で生成します。キーを標準出力やソースコードへ出力しません。ファイルをサーバー管理者が安全な方法で確認して入力してください。

公開時はHTTPSを使用します。`VITE_` をキーの名前に付けるとクライアントへ公開されるため使用しません。プロキシが宛先へのHTTPS通信時だけ置換するAPIキーとは異なり、このキーはアプリサーバー自身が検証するローカルの秘密値です。

別サイトのOriginを持つリクエストを拒否し、CORSで集計を公開しません。送信サイズ16KB・バッチ20件、接続元ごとの収集300リクエスト／分、認証失敗10回／分を上限とします。Node.js版では接続元の判定に直接の接続元を使い、任意のX-Forwarded-Forを信頼しません。リバースプロキシ配下ではそのプロキシ単位の制限になります。Cloudflare版はCloudflareが設定するCF-Connecting-IPを使用します。制限用カウンターは各プロセス／Workerインスタンス内の短期メモリで、分散した厳密な制限ではありません。公開の収集APIは人間とボットの完全な識別を行いません。

## 起動と保存先

| 項目         | 開発用 `npm run dev`               | 公開用 `npm start`             |
| ------------ | ---------------------------------- | ------------------------------ |
| アプリ／API  | 5173番                             | 3001番（PORTで変更可）         |
| DB           | `.local-data/analytics-dev.sqlite` | `.local-data/analytics.sqlite` |
| 自動生成キー | `.local-data/analytics-dev.key`    | `.local-data/analytics.key`    |

`.local-data/` はGit管理外で、静的配信される `dist/` の外側です。DBとキーファイルは権限600、作成するディレクトリは権限700です。`ANALYTICS_DB_PATH` と `ANALYTICS_ADMIN_KEY_FILE` は任意の絶対パスで上書きできます。公開用サーバーは `.env.local`、開発用Viteもサーバー側の `.env.local` を読みます。

無料の本番構成はCloudflare Workers＋Static Assets＋D1です。`cloudflare/d1-store.ts` が同じ集計仕様をD1に保存し、`cloudflare/worker.ts` がAPIとアセットを配信します。`cloudflare:dev` のローカルDBは `.wrangler/`、キーは `.dev.vars` に保存します。本番D1とは別です。公開手順・無料枠は [DEPLOYMENT.md](DEPLOYMENT.md) を参照してください。

上の表のNode.js版を外部公開する場合は、永続ディスクを持つNode.js 24環境が必要です。SQLiteを一時的なコンテナ内に置く運用は避けます。

バックアップではSQLiteのWALも考慮し、SQLiteのオンラインバックアップAPIまたは停止後の整合したスナップショットを使います。稼働中にDB本体だけをコピーすると最新の記録を失う場合があります。DB・キー・バックアップを公開静的ファイルやGitへ入れないでください。

## 構成と確認

- `src/analytics.ts`：ブラウザ識別、設定、送信キュー、プレー計測。
- `src/AnalyticsAdmin.tsx`：キー認証、期間指定、グラフ・表、CSV。
- `cloudflare/worker.ts`、`cloudflare/d1-store.ts`：Cloudflareの収集・管理APIとD1保存。
- `server/analytics-core.ts`：両環境で共有する入力・期間検証。
- `server/store.ts`：SQLite保存、重複防止、日本時間での集計、保持期間。
- `server/api.ts`：公開イベント収集と認証付き集計API。
- `server/vite-analytics.ts`：開発サーバーへのAPI組み込み。
- `server/index.ts`：公開用Web／APIサーバー。`dist/` だけを静的配信。

`npm test` で重複、永続化、日本時間の日付境界、不正入力、認証、別Origin拒否を確認します。`npm run test:e2e` では一時DBと専用キーを使い、実際のゲーム→集計→管理画面→CSV、再読み込み、計測停止、DNT、障害時の継続を確認します。
